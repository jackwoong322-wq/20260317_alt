## 무엇을 발견
- Frontend가 신규 dashboard API를 호출하지만 배포 backend에 없으면 404가 발생하는 문제가 있었다.
- 초기 최적화 구현은 신규 API 응답 크기는 줄였지만 cold path에서 전체 dashboard snapshot을 만들어 첫 로딩이 여전히 느렸다.
- Legacy chart는 coin/cycle 선택 시 중복 redraw와 toggle rebuild가 발생해 체감 지연이 있었다.

## 무엇을 수정
- `02_backend/routers/chart.py`: dashboard manifest/initial/cycle API, internal refresh endpoint, legacy full dashboard cache를 정리하고 신규 API가 필요한 범위만 조회하도록 개선했다.
- `03_frontend/src/LegacyAnalyzerApp.tsx`: shell, manifest, initial API를 병렬 fetch하고 iframe placeholder 주입 검증을 보정했다.
- `01_pairUSDT/templates/*`: manifest 기반 coin/cycle UI, `ensureCycleLoaded`, `getCycleStatus`, lazy cycle load 상태 모델을 추가했다.
- `03_frontend/public/legacy/*`, `03_frontend/dist/*`: legacy analyzer 산출물을 동기화했다.
- `01_pairUSDT/011_01_cryptoCollectorUsdt.py`: ZECUSDT를 Binance에서 직접 수집해 Supabase에 저장하도록 단순화했다.
- `01_pairUSDT/021/031/032 관련 predictor 흐름`: BTC template cycle과 current active box prediction 관련 변경을 포함했다.

## 왜 그렇게 판단
- `/api/dashboard-data`는 기존 legacy 호환을 위해 full payload로 유지하고, frontend 초기 화면은 `/api/dashboard-manifest`와 `/api/dashboard-initial-data`를 사용하도록 분리했다.
- 신규 API는 full snapshot 의존을 줄이고, lazy cycle endpoint는 요청한 coin/cycle만 가져오도록 해 cold load 병목을 줄였다.
- Render 배포 후 신규 API가 200을 반환해야 frontend 404가 사라진다.
