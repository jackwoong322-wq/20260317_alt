## What Was Found
- Bear chain prediction could end the first predicted bear box before the latest real `days_since_peak` already present in `alt_cycle_data`.
- That made the predicted box/path appear behind the current cycle data in the visualizer.
- Several older report files were already removed from the working tree and are included as cleanup.

## What Was Fixed
- `01_pairUSDT/lib/predictor/predict.py`: reads the latest current-cycle `days_since_peak` as `today_day`.
- `01_pairUSDT/lib/predictor/predict_box_bear.py`: passes `today_day` into the bear chain runner.
- `01_pairUSDT/lib/predictor/predict_box_bear_chain.py`: extends the first bear chain box end day to at least `today_day`, capped by `bottom_day`.
- Removed stale report files:
  `reports/2.md`, `reports/4.md`, `reports/49.md`, `reports/51.md`, `reports/53.md`,
  `reports/55.md`, `reports/57.md`, `reports/61.md`, and `reports/frontend-improvement-notes.md`.

## Why
- Prediction output should not visually lag behind available real current-cycle data.
- Capping by `bottom_day` keeps the extension within the predicted bottom window.
- The cleanup keeps `reports/` focused on retained issue reports.

## Tests
- `python -m py_compile 01_pairUSDT/lib/predictor/predict.py 01_pairUSDT/lib/predictor/predict_box_bear.py 01_pairUSDT/lib/predictor/predict_box_bear_chain.py`: passed.
- Smoke test with `today_day=30`: first bear chain box ended at day 30.
- Smoke test with `today_day=None`: baseline first bear chain box ended at day 24.
